## Contribution and attribution rules

- A PR record establishes the account that opened that PR; it does not by itself establish the origin of every line in a handoff package.
- Contributors should review, understand, test and meaningfully adapt the code assigned to them, and commit actual work under their own GitHub identity.
- Record implementation, tests, fixes, review, pairing and integration as they actually occurred. Do not fabricate commits, reviews or authorship.
- Distinguish code supplied through a handoff or generated with AI from a student's independently implemented changes. Follow the course's teamwork and AI-use requirements.
- If the assignment requires students' real names, confirm those names with the team before adding them; do not infer them from GitHub usernames.

## Collaboration workflow

Work is tracked in [GitHub Issues](https://github.com/PantelisZara/java-currency-converter/issues). Feature work is integrated through short-lived branches and reviewed PRs. The Project Lead reviews scope, checks, conflicts and contribution records before merging. See [Contributing](../CONTRIBUTING.md) for the detailed workflow.
